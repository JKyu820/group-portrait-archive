# 项目结构与修改指南

## 页面如何工作

打开首页时，`app/page.tsx` 渲染 `PortraitHall`。`app/layout.tsx` 设置页面语言、标题、描述和全局样式。页面从 `data/members.ts` 读取测试成员，每人有独立图像、编号、查找名称和稳定的 `memberId`。`data/portrait-layout.ts` 把两套分排配置换算成坐标，组件把坐标传给 CSS，浏览器把每张图定位到舞台。

搜索先规范化输入，可以识别全角数字和开头的井号。匹配结果按编号或查找名称筛选。点击结果、按 Enter 或点击画面中的人物，都通过同一个 `memberId` 选中。该 ID 决定高亮、变暗和资料内容。窄屏打开底部资料面板时会滚动页面，把选中人物的脸带到面板上方。

## 改动入口与画面变化

| 想改什么 | 在哪里改 | 可观察到的变化 |
| --- | --- | --- |
| 改测试人物的查找名称 | `data/members.ts` 的 `testRoster` | 搜索命中词、结果名称、资料标题和人物的可访问名称随之更新。人物脚下仍然没有文字牌 |
| 改某人的简介或资料 | `data/members.ts` 的 `testProfiles` | 点开该人物后显示新的资料。没有完整资料的成员使用简版面板 |
| 调换两人的位置 | `data/portrait-layout.ts` 的 `slots` | 两人交换在合影里的位置，编号和搜索结果仍对应原人物。桌面与手机分别调整 |
| 一排更宽、更低或更大 | 同文件的 `left`、`right`、`bottom`、`scale` | 调大横向范围会拉开一排，调大基线值会下移一排，调大缩放会增加前后遮挡 |
| 改搜索行为或高亮后滚动 | `components/portrait-hall.tsx` 的匹配与 `selectMember` | 结果筛选、选中状态或目标在屏幕上的位置变化。修改后验证空结果、编号、名称和连续切换 |
| 改颜色、合影比例、亮暗或点击区 | `app/globals.css` | 主题色、舞台高宽、前后排观感或人物可点区域变化。注意 `.portrait::after` 的点击范围独立于透明图像 |
| 改背景或站台装饰 | `public/assets/backgrounds/sunlit-paper.svg` 与 `.stage` | 舞台色彩、弧线和星点变化，人物图片仍按各自图层显示 |

### 排布规则

行从后到前定义。每个 `slots` 值对应测试编号的数字部分，桌面和手机各应恰好使用每个编号一次。行内从 `left` 到 `right` 均布，`bottom` 按舞台高度的百分比计，以图像底部中心为锚点。布局会给行中央少量下沉与放大。前排图层高于后排，选中人物再提升一层。屏幕宽度不超过 600 像素时用手机五排。宽度不超过 900 像素时用底部资料面板。

**示例。** 想让桌面第二排两侧少挤一些，可以把第二排的 `left` 从 14 调到 12，`right` 从 86 调到 88。改完查看 1440 × 900 的全景与打开右侧资料后的画面，再点两端人物和邻近人物。

### 替换测试形象

保持一个人物一张透明图。现有 SVG 使用统一的 210 × 250 画布，带脚底留白。替换为 PNG 时，先对齐透明边界、脚底和比例，再更新 `data/members.ts` 中的素材地址规则或对应条目。若轮廓差异较大，同时复核 CSS 点击区。为避免影响原型数据，新增素材优先在任务分支里用授权测试图演练。

### 如何复现并解释改动

从 [README](../README.md) 启动，先打开 `v0.1.0` 的页面截图对照基线。桌面用 1440 × 900，手机用 390 × 844。先看全景，再试 `001`、`小满`、`026` 和 `晨露`。点击前后排、关闭资料、清空搜索后确认能回到全景。浏览器自动测试跑相同的桌面和手机尺寸。若改动视觉，记录实际生效的文件、改变的值、前后截图和还需要验收的设备。
